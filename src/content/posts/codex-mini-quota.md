用 Codex 工作时，我经常想知道还剩多少使用额度、什么时候重置。这个信息不需要一直占据屏幕，但需要的时候，最好能随手看到。

于是我做了 [Codex Mini Quota](https://github.com/sjjxt/codex-mini-quota)，也叫「Mini 用量气泡」：点击 Codex 桌面客户端里的官方 Mini 宠物，就能展开一个小气泡，查看账号接口提供的用量信息。

这是一个 Windows 本地第三方扩展，与 OpenAI 无隶属关系。本文记录项目当前的设计和使用方式；具体功能与要求以仓库后续更新为准。

## 让一次查询更顺手

我想做的东西很简单：平时让 Mini 像往常一样待在桌面，需要了解余量时点一下，看看数字，再继续手头的工作。

气泡可以显示 **5 小时与每周额度的剩余百分比和重置时间**。它每 60 秒自动刷新，也提供手动刷新按钮；支持中文和 English，可以在气泡里切换，并保存语言偏好。需要恢复跟随 Codex 或 Windows 的语言时，可以从托盘菜单选择自动模式。

点击关闭按钮或按 `Esc` 可以收起气泡。项目保留 Mini 原有的点击行为，让这个入口尽量融入原本的使用习惯。

这里显示的是 **Codex 使用额度**，不是 API 的美元余额，也不是 ChatGPT 普通聊天额度。可显示哪些额度窗口，取决于账号接口实际返回的内容；接口没有提供的部分显示为「暂未提供」，不会猜成 0% 或 100%。

## 气泡里的数字从哪里来

项目通过 Codex 的 MCP 启动检查加载引导程序，再由桌面环境启动气泡组件。组件识别官方 Mini 的点击，并通过本地 Codex app-server 的 `account/rateLimits/read` 查询当前账号的额度。

```text
启动 Codex → 加载引导程序 → 启动气泡组件
                                      ↓
点击 Mini → 查询账号用量 → 显示剩余比例与重置时间
```

查询不会新建聊天，也不会发起模型生成；但它仍需使用当前登录账号连接 Codex 服务。自动刷新会带来本地进程和定时查询的开销。

选择这种方式时，我也希望尽量减少对客户端文件的侵入。项目不修改 `WindowsApps` 或 `app.asar`，但窗口识别仍依赖客户端的安装布局和界面状态，所以不能保证客户端更新后永远无需调整。

## 做成一个顺手的入口，还要处理哪些细节

第一个是启动时机。曾经停留在 Codex 首页、不进入聊天时，组件无法保持运行：启动检查结束后，临时服务进程树会被清理。后来调整为通过桌面 Explorer 启动气泡组件，让它能够在首页继续运行，同时将组件就绪和额度查询分开处理。

第二个是数据的含义。额度字段缺失和真实的 0% 是两回事；如果把缺失值当成一个确定的数字，气泡看起来虽然完整，却可能误导使用者。因此项目将缺失状态单独显示，也处理查询超时、断线和多个额度桶等情况。

第三个是安装与卸载。项目支持从新解压目录重新安装，并处理本项目旧来源的迁移；卸载时也提供设置还原的选择。一个桌面小工具除了能启动，还应该让人知道它改变了什么，以及不用时怎么退出。

## 安装与启动：方便之外也要说明影响

当前版本面向 **Windows x64**，需要安装并登录 Codex 桌面客户端、启用官方 Mini，并具备仓库列出的 Windows、Codex CLI 和 Python 运行环境。

安装时，将项目完整解压到准备长期保留的目录，双击 `install.cmd`，成功后完全退出并重启 Codex。整个目录需要保留，因为启动脚本依赖其中的 PowerShell 和 Python 文件。

有一个值得提前知道的设置：安装程序会启用 Codex 的 **全局 MCP 启动检查**。这可能让其他已启用的 MCP 服务也在启动阶段连接，增加初始化时间或要求登录。安装脚本会记录这个开关的原值；卸载时可以选择是否还原。

气泡随客户端启动加载，不需要为了查一次余量而新建聊天，也不需要另设 Windows 登录自启动。完全退出 Codex 后，气泡组件通常会在约 12 秒内退出；仅关闭主窗口而让 Codex 留在后台，可能不会重新触发加载。

## 卸载与本地记录

不再使用时，可以运行 `uninstall.cmd`，选择仅卸载，或卸载并尝试还原之前记录的启动设置。如果后来手动修改过该开关，或者没有可用的还原记录，卸载程序不会自动覆盖它。

语言偏好、设置还原记录和脱敏诊断保存在本机 `%LOCALAPPDATA%\CodexMiniQuota`。项目说明中写明，诊断不记录原始接口响应、密钥或对话，项目也没有自建遥测或上传服务。卸载后这些本地记录会保留，方便排查或恢复设置。

## 目前还不完美的地方

这个项目的窗口识别目前针对 Windows 官方 `WindowsApps\OpenAI.Codex_…` 安装布局。macOS、Linux 和其他安装布局尚未适配；多屏缩放、多个候选窗口或客户端界面变化，也可能影响 Mini 的识别。

如果额度没有显示，可能是登录或网络问题，也可能是接口本来就没有返回对应窗口。遇到问题时可以先检查登录状态并手动刷新，更多安装、升级与排错步骤放在[使用说明](https://github.com/sjjxt/codex-mini-quota/blob/main/%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E.md)中。

对我来说，这个小项目的意义是把一次频繁但短暂的查询，放到一个顺手的位置。以后我也会继续关注客户端更新带来的兼容问题，让这个小气泡尽可能安静、可靠地陪着日常工作。
